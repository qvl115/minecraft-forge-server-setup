## Forge 服务端怎么搭：先看版本分界线

服务端版本高于 1.16.5，走安装器流程；1.16.5 及以下，和原版、Paper、Fabric 一样，运行 jar 文件就完事。这条线不分操作系统，Windows 和 Linux 都一样。

### 1.16.5 及以下：下载完直接跑

以 1.12.2 为例，装好 Java 8，把 `forge-1.12.2-14.23.5.2854.jar` 和对应的 `minecraft_server.1.12.2.jar` 放进同一个目录，执行：


java -jar forge-1.12.2-14.23.5.2854.jar


第一次运行会停下来并生成 `eula.txt`，把里面的 `false` 改成 `true`，再跑一次，出现 `Done` 就成了。

想让它关掉 SSH 也不断，用 screen 挂着跑：`screen -S mc` 新建会话，在里面启动服务端，按 Ctrl+A 松开再按 D 挂到后台，回来用 `screen -r mc`。

### 1.17 及以上：先 -installServer，再 bash run.sh

以 1.21 的 `forge-1.21-51.0.23` 为例，完整流程是这样：

1. 把 `forge-1.21-51.0.23-installer.jar` 上传到服务端目录。
2. 用下面这条命令执行安装。在面板里，这就是“启动命令”那一栏：


java -Xms128M -XX:MaxRAMPercentage=95.0 -Dfile.encoding=UTF-8 -Duser.country=CN -jar forge-1.21-51.0.23-installer.jar -installServer


3. 等终端出现 `The server installed successfully`。
# -Xmx4G` 这一行，把开头的 `#` 删掉，数字改成你实际能给的内存。
5. 把启动命令换成 `bash run.sh`。
6. 再次启动，出现 EULA 提示后编辑 `eula.txt`，`false` 改 `true`。
7. 重启，出现 `Done` 就可以进服了。

这条安装命令里的几个参数值得单独说清楚，前排教程抄来抄去经常漏掉解释：

- `-installServer`：告诉 Forge 这次是安装服务端，不是启动游戏。
- `-XX:MaxRAMPercentage=95.0`：JVM 最多能用系统可用内存的 95%。小内存机器上它比写死 `-Xmx` 好用，但真正决定服务端能吃多少内存的是 `user_jvm_args.txt`。
- `-Dfile.encoding=UTF-8`：文件编码设成 UTF-8，不加这个中文会乱码。
- `-Duser.country=CN`：地区设为 CN，部分服务端和插件会据此切中文、走国内镜像下载。
- `-Xms128M`：初始堆内存 128M。安装阶段用不了多少，给大了浪费。

`user_jvm_args.txt` 这一步最容易漏。`run.sh` 会读这个文件里的 JVM 参数，而文件里那行 `-Xmx` 默认是被 `#` 注释掉的，不改等于没设上限，服务端可能把整台机器的内存吃满，然后被系统杀掉。教程里的机器是 8G，作者改成 `-Xmx7G`，留 1G 给系统。这个值不能超过服务器的物理内存。

### eula.txt 和 server.properties 这两个文件必须改

`eula.txt` 是必过的一关，首次启动一定报 `You need to agree to the EULA in order to run the server`，改一行就行：`eula=false` 换成 `eula=true`。

`server.properties` 里真正影响开服的没几项，其余保持默认：

| 参数 | 默认值 | 什么时候要改 |
| --- | --- | --- |
| `online-mode` | `true` | 有离线玩家要进就改 `false`，改之前先 stop |
| `server-port` | `25565` | 一台机器开多个服，或端口被占用 |
| `max-players` | `20` | 按实际人数调 |
| `view-distance` | `10` | 卡顿就往下调到 6 |
| `max-tick-time` | `60000` | 想避免超时崩服可以设 `-1` |
| `white-list` | `false` | 离线服建议用插件或模组做白名单 |
| `server-ip` | 空 | 不清楚在改什么就别动 |
| `motd` | `A Minecraft Server` | 多人列表里显示的名字 |

## 会卡住人的四个地方

**Forge 的 library 缺失报错。** 在服务端跑 Forge 时会出现“无法建立 library”这类报错，原因是 Forge 依赖的库没下全。可用的做法是单独下载一份 library 包，解压后和服务端目录合并。这个问题在 1.12.2 时代比较常见；高版本 Forge 的安装器会自动拉依赖，是否还遇到要看当时的网络情况。

**CentOS 7 装不了 MCSManager。** 纯命令行跑 Forge 服务端，CentOS 7 完全够用，`yum install java-1.8.0-openjdk.x86_64` 之后就能开 1.12.2。装 MCSManager 面板就不行，安装时会提示操作系统版本过低。要用面板就换 Ubuntu 24.04 LTS 或者 CentOS 8 以上。这条直接决定你买机器时选哪个系统镜像，买完再换系统要重装。

**换存档后的权限。** 用非 root 用户跑服务端（比如专门建一个 `mcfabricuser`），替换 `world` 文件夹之后必须把整个服务端目录的属主改成这个用户：


sudo chown -R mcfabricuser:mcfabricuser /minecraft


不改的话服务端写不进 world 目录，起不来。用 root 跑没这个问题，但长期用 root 跑服务端不是好习惯。

**关服不用 stop 会回档。** 直接关窗口、kill 进程、在面板里点强制停止，都可能丢存档。正确做法是在服务端控制台输入 `stop`，等它自己保存完退出。这一条没有例外。

## 配置怎么估：4 核 8G 是底线，单核比核心数重要

Forge 服吃单核和内存。1.21 这类高版本 Java 服，配置建议 4 核 8G 起，最低别低于这个数，CPU 要挑高主频的，i9 14900K、Ryzen 5900X 这个级别。16 核但单核弱的机器，跑大型模组包照样掉 TPS，玩家走两步回弹一步。

Java 版本也要对上：1.21 配 Java 21，1.12.2 配 Java 8。装错了服务端直接起不来，报错信息通常很含糊，先在这一步排查。

零预算的做法是用两台电脑，一台专门跑服务端，一台玩。只有一台机器的话，内存不够会卡得很明显。

## 面板开服和自己搭，差在哪

自己搭一遍 Forge 服，要做的事包括：买机器、选系统镜像、开端口、SSH 登录、装 Java、上传 jar、改启动命令、跑安装器、改 `user_jvm_args.txt`、改 `eula.txt`、改 `server.properties`、装 screen 或配 systemd 保活、配端口映射。前面提到的四个问题全在这个清单里。

面板服把这些收进了一个网页控制台：选服务端类型和版本，点启动，EULA 在文件管理里改，模组传到 `mods` 目录，端口在面板里转发。代价是自由度低一些，自定义 jar、特殊启动参数、非常规目录结构会受限制。

你打算长期折腾、要完全控制服务端的每一个文件，就继续用 VPS 手搭；你只想让服务端稳定跑着、朋友能进来玩，面板省下的时间比省下的钱值钱。雨云游戏云这套面板对 Forge 是按版本直接开的，不用你走一遍 `-installServer`。

## 常见问题

**离线模式怎么开？**
先在控制台输入 `stop` 关服，再编辑 `server.properties` 把 `online-mode` 改成 `false`，保存后重启。运行中改这一项不生效，而且容易把存档写坏。

**25565、23333、24444 分别是什么端口？**
`25565` 是 Minecraft 服务端默认端口，玩家连的是这个。`23333` 是 MCSManager 面板的 Web 端口，`24444` 是面板守护进程用的端口。用 NAT 共享 IP 时这三个都要做端口转发，玩家要填的是转发后的公网端口，不是 25565。

**Forge 服能装插件吗？**
Forge 本身只加载模组，插件走的是 Bukkit/Spigot 那一套。想让模组和插件一起跑，得用 Mohist 这类融合端，Mohist 目前只更新到 1.20.2，1.21 没有。

**模组要服务端和客户端都放吗？**
分两类。服务端模组（比如连锁采集）必须两边都有且版本一致，只放一边不生效。客户端模组（比如小地图）放本地就行，传不传服务器都能用。省事的做法是本地和服务器保持同一份模组列表。

**原版 server.jar 能加模组吗？**
不能，必须换成 Forge 或 Fabric 服务端。
